# CommentScope 开发工作流

这份文档定义项目的协作方式。**每个 agent（包括人）开工前都必须读过它。**

---

## 1. 角色

| 角色 | 谁 | 什么时候在场 | 职责 |
|---|---|---|---|
| **产品负责人** | 用户 | 随时 | 提需求、做决策、里程碑验收、人工标注 |
| **编排 agent** | 常驻对话中的助手 | 常驻 | 拆任务卡、分发、汇总、维护任务列表与项目记忆；**唯一和用户对话的入口** |
| **dev** | 按需创建的子 agent | 单个任务期间 | 按任务卡写代码 |
| **reviewer** | 按需创建的子 agent | dev 完成后 | 只读审查，对照任务卡的验收标准逐条核对 |
| **tester** | 按需创建的子 agent | reviewer 通过后 | 写测试、跑测试、报告结果 |

## 2. 流水线

```
用户提需求
   ↓
编排 agent 写任务卡（引用 PRD 章节 + 交付物路径 + 验收标准）
   ↓
dev 实现 ──→ reviewer 审查 ──→ tester 测试
   ↑                                │
   └────── 打回重做 ←───────────────┘
   ↓
编排 agent 汇总结果给用户
   ↓
用户拍板 → 合并到 main
```

## 3. 铁律（违反任何一条，打回）

1. **写代码的 agent 不审查自己的代码。** reviewer 必须是全新的 agent 实例。
2. **每个任务必须有验收标准**，不达标不合并，没有例外。
3. **评论是外部不可信输入**（PRD 决策 D4）：截断长度、过滤指令性文本、不落盘用户身份。
4. **模型版本锁 `jev-1.13.0`**（PRD 决策 D3），任何地方不得出现 `jev-latest`。
5. **人工标注环节（M1 的 200 条）必须用户亲自参与**，agent 只能准备标注界面和统计脚本。
6. **数据只走公开接口**，并发 ≤ 3，落盘匿名化。

## 4. Git 约定

- `main`：稳定分支，只接受经过完整流水线的合并
- 功能分支：`feature/m0-bilibili-fetch` 这种命名（里程碑-内容）
- commit message 用 conventional commits：
  - `feat:` 新功能
  - `fix:` 修 bug
  - `docs:` 只改文档
  - `test:` 只改测试
  - `chore:` 构建、配置、脚手架
- 一个 commit 只做一件事

## 5. 任务卡模板

编排 agent 给 dev/reviewer/tester 派活时，一律用这个格式。**子 agent 看不到对话历史，
任务卡是它们唯一的信息来源，写清楚是编排 agent 的责任。**

```markdown
# 任务卡：<一句话任务名>

## 背景
为什么做这件事。引用 PRD 的具体章节号，不要复述全文。

## 交付物
改哪些文件、新建哪些文件，全部用绝对路径列出。
运行入口是什么（命令 / 函数）。

## 验收标准（reviewer 按此逐条核对）
- [ ] 可验证的条件 1
- [ ] 可验证的条件 2

## 边界（明确不要做的事）
- 不要动 xxx
- 不要引入新依赖，除非……

## 参考上下文
- PRD：C:\Users\Y9000\Desktop\EchoLens\PRD.md（读第 X 节）
- 相关代码：<绝对路径>
- 本工作流：C:\Users\Y9000\Desktop\EchoLens\docs\WORKFLOW.md
```

## 6. 目录结构对照（PRD 6.2 的四层架构）

```
echolens/
├── fetch/      数据层：B站公开接口、JSONL 缓存
├── judge/      判断层：Provider 抽象、Jev 客户端、防注入过滤、9 个分类问题
├── analyze/    分析层：聚合统计、规则建议引擎、主题归因
└── report/     呈现层：HTML 报告、竖版 PNG、CLI
```

层与层之间只通过 JSONL 文件传递（`data/` 目录），任何一层可以单独重跑。
